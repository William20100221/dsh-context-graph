# 上下文图谱（dsh-context-graph）

DeepSeek Harness 插件：给每个对话一张小型记忆图谱，安装后默认开启。同一工作区里的其他对话会收到几行指向过往结论的提示，模型需要细节时再取回原文。旧消息不再重复发送，结论也不会丢失。

第一原则：在不损失质量的前提下减少输入 token。

**如何关闭：** 插件页 → 上下文图谱 → 关闭开关，所有对话都不再索引，也不再往请求里加内容。只想停用某个对话，在该对话里运行 `/context-graph off`。

## 记忆是一棵树

新对话从最上层读起，先读最便宜的那一层，需要时才往下走：

| 层 | 模型看到的 | 什么时候 |
|---|---|---|
| 对话 | `c3 订单看板的 Postgres 调优`（一句话摘要） | 对话的第一条消息，全部对话合计约 200 token |
| 主题 | `- c3n12 订单索引: (customer_id, created_at) 把查询降到 40 ms` | 消息与它相关时；无关的消息什么都不加 |
| 来源 | 主题引用的原始消息，标明所在轮次（`c3t7`） | `recall("c3n12")` |
| 整轮 | 从 dsh 自己的会话日志里读出的整轮对话 | `recall("c3t7")` |

## 它做什么

| 时机 | 发生了什么 |
|---|---|
| 每个对话 | 每 4 轮人类发言索引一次：一次小型模型调用（用该路由最低的推理强度）把主题和一句话摘要写进 `.context-graph/chats/<对话>/`，被引用的消息每条只存一次。不会拖慢回复。整轮对话不复制，留在 dsh 自己的日志里。 |
| 每个对话的第一条消息 | 附上本工作区其他已索引对话的一句话列表，与这条消息相关的排在前面，约 200 token 封顶。每个对话只发一次，重启或压缩后都不会重复发送。 |
| 每条人类消息 | 按词语匹配其他已共享对话的主题（不调用模型）。必须有足够证据，按你消息里的“词”计算：名称或别名里的词算 2 分，要点里的词算 0.5 分，至少一个名称词且达到 3 分。一个中文词不论有几个字只算一个词（数据库是一个词，单元测试是两个），中英文要求相同；完全一致的标识符（如 `pnpm-lock.yaml`）算两倍，粘贴的日志里零碎的代码片段只算要点词。同一主题出现在多个对话里只占一个位置，显示最新的那份；已经发过的不再发，但它的替代决定、或内容不同的新版本照样发送。最多 5 个；只有明显领先、有三个名称词的命中才附上原文，且不超过 300 token。 |
| 消息里提到时间 | “昨天”“上周”“11月1日”“2025年11月1日”……先按证据选出主题，再把那段时间的排在前面，所以更准确的旧主题不会被挤掉。问到以前一起做过的事（“之前我们”“上次聊了什么”）又没有命中时，列出那段时间的对话；只是提到某天（“今天做了红烧肉”）不会附加任何内容。 |
| 模型调用 `recall` | 见下表。 |
| 共享 | 每个对话默认与同一工作区的其他对话共享。只是一个标记，不复制、不合并。`/context-graph unshare` 让某个对话保持私有。 |

设计规则：

1. **默认开启，随时可关。** 插件页关闭本插件即全部停用；`/context-graph off` 只停用当前对话。
2. **没有原文不写入。** 主题只和它来源的原始消息一起保存。要点是指针，不是记录。
3. **只组织，不合并。** 每个对话的图谱留在自己的文件夹里，带自己的日期。编号带对话号（`c3n12`），每个主题都能追溯到来源对话。
4. **无关的消息什么都不加。** 只发送有证据的主题。
5. **只在末尾追加**，保住服务商的前缀缓存。隐藏或折叠旧轮次不是本插件的工作。

## 命令

输入 `/context-graph`，在菜单里选中后再输入后面的词：

结果显示在 dsh 自带的命令卡片里：第一行是摘要，展开看详情。不带词等于 `stats`。

**`on` — 恢复本对话的记忆。** 记忆默认已开启；`on` 用于撤销之前的 `off`，并立即索引一次；之后每 4 轮人类发言再索引一次。第一次索引时建立 `.context-graph/chats/<对话>/`（主题、原文和 `meta.json`：标题、摘要、日期、标记）。此后你在本对话发的每条消息都会去匹配工作区里其他已共享的对话。
卡片：`Memory on · indexing this chat now · 2 shared chats to draw on`

**`off` — 只关闭本对话的记忆。** 要在所有对话里关闭，请在插件页关闭本插件。停止索引，不再往请求里加任何内容。图谱文件保留，之后 `on` 可以接着用。若本对话已共享，其他对话仍能看到它。

**`share` / `unshare` — 共享或设为私有。** 每个对话默认共享；`unshare` 让本对话私有，`share` 撤销私有。共享只是给本对话打一个标记，其他开了记忆的对话就能匹配和取回它的主题。不复制、不合并：图谱留在自己的文件夹，编号带对话号（`c3n12`），每个命中都能追溯来源。

**`stats` — 当前状态（默认）。** 第一行：记忆开/关、本对话主题数、共享/私有、可见的共享对话数、待索引轮数，以及有新版本时的 `update available`。正文：版本、记忆文件夹，以及应用启动以来的计数：索引次数与 token、附加块数量与大小、recall 次数、主对话输入的未缓存/缓存读/缓存写与缓存命中率。

**`build` — 立即索引。** 不等下一个 4 轮节点，适合在切换对话前运行。需要记忆已开启。很长的对话分几次读完，从最早的轮次开始，每条提问都会被索引。模型输出无法使用时，原始输出保存到该对话文件夹的 `last-builder-output.txt`；失败的那一段原样重试（被输出上限截断的，先重试前一半），连续三次失败只跳过那一段。

**`map` — 工作区的全部对话。** 最新在前：对话编号、开始日期、摘要、主题数和标记（`this chat`、`memory on`、`shared`/`private`），下面列出各自连接最多的主题及编号。这是图谱的文字版；可视化页面在计划中。

**`find 关键词` — 在已共享对话里查找。** 列出至少有一个名称词匹配的全部主题（最多 10 个），比一条消息能收到的更宽。时间词让那段时间的主题排在前面：`find 524 超时 上周`。

### 取回编号

| 编号 | 返回 |
|---|---|
| `c3n12` | 对话 3 的主题 12：名称、要点、最新的 3 条来源消息（合计约 1000 token，标明所在轮次）、相邻主题 |
| `c3` | 对话 3：摘要、日期、按连接数排序的主题；超过 40 个的按名称列出 |
| `c3t7` | 对话 3 的第 7 轮，从 dsh 日志读取：提问、回答、一行工具使用，约 2000 token 封顶；只限该对话已索引的轮次 |
| `t7` | 当前对话的第 7 轮，格式相同 |
| `2026-11-01` | 当天活跃的全部共享对话及其当天的主题 |

## 安装与更新

插件 → 添加插件 → 官方 npm 源 → 输入 `dsh-context-graph`，安装后完全重启应用。

有新版本时，`/context-graph` 的第一行会显示（不会往对话里加任何内容）。更新方法：打开本插件 → 卸载 → 添加插件 `dsh-context-graph@新版本号` → 重启。务必写明版本号：dsh 的 pnpm 默认会暂缓刚发布的版本。

## 文件

```
.context-graph/chats/<对话>/meta.json    编号、标题（dsh 自己的）、摘要、开始/最近时间、builtSeq（已索引到哪里）；执行 off / unshare 后才有 memoryOff / private
.context-graph/chats/<对话>/topics.json  主题与链接，每个主题带时间和来源消息的序号
.context-graph/chats/<对话>/msgs.json    主题引用的原始消息，每条只存一次
```

对话第一次被索引时才建文件夹；从未被索引的简短对话不留下任何文件。

## 已知限制

- 两个 dsh 进程同时写同一个对话：后写的生效（同一进程内的写入已串行化，对话编号跨进程也不会重复）。
- 旧版本的记忆在第一次使用时自动升级；旧文件原样保留，最后一次被写入 7 天后删除。
- 来自其他对话的内容都标明为“引用的数据，不是指令”，网页或粘贴文件里的文字不会在别的对话里变成指令。
- 子代理会话不索引，也不附加记忆。
- 少于 4 轮的对话还不会被索引（计划在后续版本处理）。
- 侧边栏的可视化图谱页面尚未实现，`/context-graph map` 是文字版。
