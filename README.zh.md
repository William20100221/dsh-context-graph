# 上下文图谱（dsh-context-graph）

DeepSeek Harness 插件：给每个对话一张小型记忆图谱，安装后默认开启。同一工作区里的其他对话会收到几行指向过往结论的提示，模型需要细节时再取回原文。旧消息不再重复发送，结论也不会丢失。

第一原则：在不损失质量的前提下减少输入 token。

**如何关闭：** 插件页 → 上下文图谱 → 关闭开关，所有对话都不再索引，也不再往请求里加内容。只想停用某个对话，在该对话里运行 `/context-graph off`。

## 记忆是一棵树

新对话从最上层读起，先读最便宜的那一层，需要时才往下走：

| 层 | 模型看到的 | 什么时候 |
|---|---|---|
| 对话 | `c3 订单看板的 Postgres 调优`（一句话摘要） | 每个对话一次，随它第一次收到的主题提示或第一个关于过往的提问发送，全部对话合计约 200 token |
| 主题 | `- c3n12 订单索引: (customer_id, created_at) 把查询降到 40 ms` | 消息与它相关时；无关的消息什么都不加 |
| 来源 | 主题引用的原始消息，标明所在轮次（`c3t7`） | `recall("c3n12")` |
| 整轮 | 从 dsh 自己的会话日志里读出的整轮对话 | `recall("c3t7")` |

## 它做什么

| 时机 | 发生了什么 |
|---|---|
| 每个对话 | 每 4 轮索引一次：一次小型模型调用（用该路由最低的推理强度）把主题和一句话摘要写进 `.context-graph/chats/<对话>/`，索引读过的每条消息完整保存一次。不会拖慢回复。一轮是 dsh 为你运行的任何一轮：你输入的消息、`/goal` 的每一轮、定时提醒、对模型提问的迟到回答。没到下一个 4 轮就停下的对话，安静 30 分钟后、或同一工作区开始新对话时再索引一次，两次常规索引之间最多一次；此后再开新对话，5 分钟后才索引它（期间回到它就取消），在别的对话里问个小问题不花索引。取回整轮时优先读 dsh 自己的日志，日志不在了就读保存的消息。 |
| 第一次收到主题提示、或第一次问到过往的事 | 附上本工作区其他已索引对话的一句话列表，与这条消息相关的排在前面，约 200 token 封顶。每个对话只发一次，重启或压缩后都不会重复发送；与记忆无关的第一条消息什么都不加。 |
| 每条人类消息 | 按词语匹配其他已共享对话的主题（不调用模型）。必须有足够证据，按你消息里的“词”计算：名称或别名里的词算 2 分，要点里的词算 0.5 分，至少一个名称词且达到 3 分。一个中文词不论有几个字只算一个词（数据库是一个词，单元测试是两个），中英文要求相同；英文复数按单数匹配（`tests` 能找到 `test`），少数产品名（`Windows`、`Teams`、`Sheets`、`Pages`、`Actions`）保持原样；`loadViews` 这样的驼峰标识符也拆成 `load` 和 `views`；完全一致的标识符（如 `pnpm-lock.yaml`、`loadViews`）在主题里写法相同时算两倍，粘贴的日志里零碎的代码片段只算要点词。同一主题出现在多个对话里只占一个位置，显示最新的那份；已经发过的不再发，但它的替代决定、或内容不同的新版本照样发送。最多 5 个；只有明显领先、有三个名称词的命中才附上原文，且不超过 300 token。 |
| 消息里提到时间 | “昨天”“三天前”“大前天”“上周”“上上周”“一周前”“上个月”“11月1日”“2025年11月1日”“last Monday”“November 3rd”……先按证据选出主题，再把那段时间的排在前面，所以更准确的旧主题不会被挤掉。问到以前一起做过的事（“之前我们”“上次聊了什么”）又没有命中时，列出那段时间的对话，当天实际工作过的排在前面，约 1000 token 封顶；只是提到某天、计划某天或讲某天的事（“今天做了红烧肉”“我们明天要讨论什么”）不会附加任何内容。 |
| 模型调用 `recall` | 见下表。 |
| 共享 | 每个对话默认与同一工作区的其他对话共享。只是一个标记，不复制、不合并。`/context-graph unshare` 让某个对话保持私有。 |

设计规则：

1. **默认开启，随时可关。** 插件页关闭本插件即全部停用；`/context-graph off` 只停用当前对话。
2. **没有原文不写入。** 主题只和它来源的原始消息一起保存。要点是指针，不是记录。
3. **只组织，不合并。** 每个对话的图谱留在自己的文件夹里，带自己的日期。编号带对话号（`c3n12`），每个主题都能追溯到来源对话。
4. **无关的消息什么都不加。** 只发送有证据的主题。
5. **只在末尾追加**，保住服务商的前缀缓存。隐藏或折叠旧轮次不是本插件的工作。

## 命令

输入 `/context-graph`，在菜单里选中后再输入后面的词：

结果显示在 dsh 自带的命令卡片里：第一行是摘要，展开看详情。不带词等于 `stats`。

**`on` — 恢复本对话的记忆。** 记忆默认已开启；`on` 用于撤销之前的 `off`，并立即索引一次；之后每 4 轮再索引一次，对话安静下来时补一次。第一次索引时建立 `.context-graph/chats/<对话>/`（主题、原文和 `meta.json`：标题、摘要、日期、标记）。此后你在本对话发的每条消息都会去匹配工作区里其他已共享的对话。
卡片：`Memory on · indexing this chat now · 2 shared chats to draw on`

**`off` — 只关闭本对话的记忆。** 要在所有对话里关闭，请在插件页关闭本插件。停止索引，不再往请求里加任何内容。图谱文件保留，之后 `on` 可以接着用。若本对话已共享，其他对话仍能看到它之前共享的内容。记忆关闭期间输入的内容永远不会被索引、共享或保存，打开 `on` 之后也不会；那一段也不会成为对话的标题。在这期间设定的 `/goal`（它的每一轮，`on` 之后和之后分叉出的对话里也一样）、安排的提醒（触发时）以及你对模型提问的回答同样如此。若在一轮对话仍在进行、或你输入的消息还在排队时执行 `on`，它会在对话空闲时才生效，这些内容同样保持私有。

**`share` / `unshare` — 共享或设为私有。** 每个对话默认共享；`unshare` 让本对话私有，`share` 撤销私有。分叉出的对话从第一条消息起：父对话私有则私有；分叉点处记忆是关闭的，则记忆关闭。共享只是给本对话打一个标记，其他开了记忆的对话就能匹配和取回它的主题。不复制、不合并：图谱留在自己的文件夹，编号带对话号（`c3n12`），每个命中都能追溯来源。

**`stats` — 当前状态（默认）。** 第一行：记忆开/关、本对话主题数、共享/私有、可见的共享对话数、待索引轮数，以及有新版本时的 `update available`。第二行是记忆在本对话和整个工作区节省了多少（估算，见下文）。正文：版本、记忆文件夹，以及应用启动以来的计数：索引次数与 token、附加块数量与大小、recall 次数、主对话输入的未缓存/缓存读/缓存写与缓存命中率。

**`build` — 立即索引。** 不等下一个 4 轮节点，适合在切换对话前运行。需要记忆已开启。很长的对话分几次读完，从最早的轮次开始，每条提问都会被索引。模型输出无法使用时，原始输出保存到该对话文件夹的 `last-builder-output.txt`；失败的那一段原样重试（被输出上限截断的，先重试前一半），连续三次失败只跳过那一段。

**`map` — 工作区的全部对话。** 结果会留在会话日志里，所以只列出最新的 40 个，并注明还有多少个；完整的树在侧边栏的“记忆树”里。最新在前：对话编号、开始日期、摘要、主题数和标记（`this chat`、`memory on`、`shared`/`private`），下面列出各自连接最多的主题及编号。这是图谱的文字版；图形版是侧边栏的“记忆树”（见下）。

### 记忆树

侧边栏的 **记忆树**（在“新建会话”下面，和“自动化任务”在一起）把一个工作区的记忆画成一棵树，根在左边：工作区、它的主题领域（按各领域最新对话的顺序，尚未分类的放最后）、领域下的对话、每个对话的主题（按类型分组：决定、事实、任务、产物、待定问题），以及每个主题来自的消息和它们的轮次编号。这就是搜索和 recall 一层层走过的那几层。

**先按领域搜索。** 索引会为每个对话命名一个大的主题领域（例如“地球与空间科学”“笔记本电池保养”），优先沿用工作区里已有的领域，所以同一领域的对话会归到一起；之前索引的对话会在所在工作区下次索引后，用一次小调用补上领域。消息提到某个领域（包含它一半以上的词）时，先在这个领域的对话里找主题；找不到再在所有对话里找；还找不到就停止。若提到了领域却什么都没找到，而消息是在问之前的工作，模型会收到一行提示，列出这个领域的对话（每个对话里每个领域只提示一次），方便它用 `recall` 取回。

- **展开与收起。** 最新的几个对话一开始是展开的，直到主题占满 40 行；收起的对话会显示它有多少个主题。点击对话展开或收起。点击主题，旁边的面板会显示它的要点、所属对话、相关主题、来源消息和可以粘贴到消息里的编号（`c3n12`），这个主题也会展开出它的消息。点击对话可以看到它的日期、标记和节省。
- **查找。** 搜索会展开有匹配的对话并淡化其他主题；类型按钮会淡化其他类型。鼠标停在某个节点上时，除了它的“家族”（上级、下级和它关联的主题）以外都会淡化。
- **键盘。** 用 Tab 进入树，上下键移动，右键展开或进入，左键收起或回到上级，Home/End 到两端，Enter 或空格打开详情。
- **动效。** 展开的部分从上级节点里长出来，移动的部分平滑地移到新位置；系统要求减少动态效果时不做动画。
- **标签。** 对话详情会显示它的类型和项目；一个对话里有几段不同的对话时，还会列出各段（`t1–t4 · 修复问题：登录跳转`）。对话详情也会显示它的领域。工具栏最右边的 **按标签排序** 会改为按类型分组，再点一次恢复按领域分组。这个选择在关闭并重新打开 DeepSeek Harness 后仍会保留。
- **隐藏对话。** 对话详情里有 **从记忆中隐藏**：其他对话不再匹配、列出、汇总或取回它，所以不占输入 token，隐藏期间也不索引。它会移到“已隐藏”分支；**重新使用** 让它回来，索引会接着补上。
- **删除对话的记忆。** 只对已在 DeepSeek Harness 中归档或删除的对话（树里会标出）：**删除记忆** 会先确认，然后永久删除它的主题和保存的消息。删除后不会再回来：正在进行的索引会丢弃结果；从归档恢复并继续使用的对话会作为新编号的对话，只从之后的内容重新开始。

**在对话里。** 对话标题栏会显示它是哪一个记忆分支（`c4`，在模式旁边），点击即可在记忆树中打开这个对话。侧边栏里对话的菜单有 **归档并清除记忆**：确认后，dsh 会归档这个对话（之后可以从归档中恢复），它的记忆会被删除（无法恢复）。只有有记忆的对话才会显示这一项。

插件 → 上下文图谱 这一页显示每个工作区里记忆节省和花费了多少。两个页面都是你自己的视图，私有、隐藏和关闭了记忆的对话也会显示并标出。数据来自只对本机主人开放的接口；会改动记忆的两个（隐藏、删除）还要求一个只有这个页面会发送的请求头，不会往任何对话里加内容。

### 记忆节省了多少（估算）

记忆不是免费的：每条笔记都是输入，笔记留在对话里，之后每次请求都会作为（较便宜的）缓存输入再发送一次；`recall` 工具随每次请求发送；索引是一次模型调用。它节省的是你手动把旧上下文带回来的成本。估算按对话分别统计两边，再按工作区汇总：

| | 计算方式 |
|---|---|
| 节省 | 模型实际用到的每个主题（被取回，或回答里出现了它的两个词而你的消息里没有）最新引用的几条消息（最多三条），按保存的文本计；同一条消息在一个对话里只算一次，无论有几个主题引用它 |
| 开销 | 发送的笔记和取回内容、它们仍在对话中时的缓存再发送（×0.1，从它分叉出的子代理发送的也算）、每次请求附带的 recall 工具（×0.1）、索引调用（缓存输入 ×0.1，输出 ×4） |
| 净值 | 节省减开销，单位为输入 token；亏损时如实显示 |

这是估算：插件无法知道没有记忆时你会粘贴什么。它偏保守：只有回答表明用到了的主题才算（只是重复你的问题不算），你本来要粘贴的内容只算一次，最多算一个主题最新的三条消息（长消息只保留开头和结尾），不算重复发送，模型重新推导旧结论所花的时间完全不计。计数保存在 `.context-graph/ledger/`，每个对话一个小文件，只存不为零的计数，每轮最多写一次、只写该对话自己的文件；同步工具占用其中某个文件时，卡片会显示“暂时无法读取节省数据”，而不是报错。

**`find 关键词` — 在已共享对话里查找。** 列出至少有一个名称词匹配的全部主题（最多 10 个），比一条消息能收到的更宽。时间词让那段时间的主题排在前面：`find 524 超时 上周`。

### 取回编号

| 编号 | 返回 |
|---|---|
| `c3n12` | 对话 3 的主题 12：名称、要点、最新的 3 条来源消息（合计约 1000 token，标明所在轮次）、相邻主题 |
| `c3` | 对话 3：摘要、日期、按连接数排序的主题；超过 40 个的按名称列出 |
| `c3t7` | 对话 3 的第 7 轮（dsh 自己的轮次编号），从 dsh 日志读取：提问、回答、批准的计划、你对模型提问的回答、一行工具使用，约 2000 token 封顶；只限该对话已索引的轮次 |
| `t7` | 当前对话的第 7 轮，格式相同 |
| `2026-11-01` | 当天活跃的全部共享对话及其当天的主题，约 1000 token 封顶，放不下的列出名称 |

## 安装与更新

插件 → 添加插件 → 官方 npm 源 → 输入 `dsh-context-graph`，安装后完全重启应用。

有新版本时，`/context-graph` 的第一行会显示（不会往对话里加任何内容）。更新方法：打开本插件 → 卸载 → 添加插件 `dsh-context-graph@新版本号` → 重启。务必写明版本号：dsh 的 pnpm 默认会暂缓刚发布的版本。

## 文件

```
.context-graph/chats/<对话>/meta.json    编号、标题（dsh 自己的）、摘要、首条提示的指纹（firstKey）、开始/最近时间、builtSeq（已索引到哪里）；执行 off / unshare / 隐藏后才有 memoryOff / private / hidden
.context-graph/chats/<对话>/topics.json  主题与链接，每个主题带时间和来源消息的序号
.context-graph/chats/<对话>/msgs.json    索引读过的每条消息，完整保存（每条最多 200,000 个字符），每条只存一次；记忆关闭期间输入的内容永远不存
.context-graph/ledger/<对话>.json        一个对话的节省估算：只存不为零的计数
```

对话第一次被索引时才建文件夹；从未被索引的简短对话不留下任何文件。从 0.13.0 起，对话会完整保存索引读过的每条消息（你和模型的文字，不含工具输出），所以即使它的 dsh 会话被删除，主题和整轮仍能完整读取；之前索引的对话会在 0.13.0 第一次启动时、趁会话还在时从 dsh 的日志补全一次。发给模型的内容不变：recall 仍按原来的 token 预算。0.9.0 及更早版本保存的轮次编号按输入的提问计数；该对话下次被索引、或它的主题被取回时，改为 dsh 自己的轮次编号，在此之前来源不标轮次。

## 已知限制

- 两个 dsh 进程同时写同一个对话：后写的生效（同一进程内的写入已串行化，对话编号跨进程也不会重复）。
- 旧版本的记忆在第一次使用时自动升级；旧文件原样保留，最后一次被写入 7 天后删除。
- 来自其他对话的内容都标明为“引用的数据，不是指令”，网页或粘贴文件里的文字不会在别的对话里变成指令。
- 子代理会话不索引，也不附加记忆。
- 工具输出不会被索引，也不在取回的整轮里（只有一行工具名称），批准的计划和你对模型提问的回答除外。
- 区分“问以前的事”和日常聊天也是按词语判断：讲某天做过的事的日常请求（“找一个像昨晚那道咖喱的菜谱”）仍可能收到一小段当天摘要。
- 在 dsh 的提醒管理器里（对话之外）修改的提醒内容，在记忆开启时触发，会像新输入一样被索引，即使修改发生在记忆关闭期间。
- 记忆树按字母数估算标签宽度，不按实际字体：全是宽大写字母的标签可能略微超出它的圆角框（鼠标悬停可看全文）。树里显示超过 400 行时，新展开的部分直接出现，没有动画。`/context-graph map` 是文字版。
- 节省数字是估算；新启动（不是从对话分叉）的子代理不计 recall 工具的份额。
- 若某个对话的 meta.json 损坏、且记忆关闭的区段读不回来，它在下次 `on` 之前的轮次对其他对话保持关闭（主题仍可用），在这一段里分叉出的对话从记忆关闭开始。

| 做法 | 来源 | 许可 |
|---|---|---|
| 整齐树布局：每层一列，上级居中于下级，同一上级的节点比不同上级的更近（Reingold-Tilford，经 Buchheim 等人改进）；水平曲线连线；展开时分支从上级长出 | [D3](https://d3js.org)（`d3-hierarchy`、`d3-shape`、可折叠树示例），Observable | ISC |
| 每列的宽度等于该列最宽的节点 | [AntV G6](https://g6.antv.antgroup.com) compactBox 布局，蚂蚁集团 | MIT |
| 一开始只展开前几层；淡化节点家族以外的内容 | [Apache ECharts](https://echarts.apache.org) 树图（`initialTreeDepth`、`emphasis.focus`），最初由百度开发 | Apache-2.0 |
| 动效：300 毫秒，移动用 emphasized 缓动，出现用 emphasized decelerate | [Material Design 3](https://m3.material.io/styles/motion/easing-and-duration/tokens-specs)，Google | Apache-2.0 |
| 键盘与角色：一个 Tab 停靠点、方向键、带层级、位置、展开和选中状态的 `tree` / `treeitem` | [WAI-ARIA 树视图模式](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)，W3C；微软 Fluent UI 和 GitHub Primer 也遵循它 | W3C（仅模式） |
