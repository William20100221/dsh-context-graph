# 上下文图谱（dsh-context-graph）

DeepSeek Harness 插件：把过往对话记成一张小型主题图谱，并把长对话的旧轮次折叠成目录，让每次请求少发送输入 token。需要细节时，模型按目录找到原文。

## 它做什么

| 时机 | 发生了什么 |
|---|---|
| 每 4 轮人类发言 | 回合结束后，用一次小型模型调用把新内容整理进 `.context-graph/graph.json`，并原样保存被引用的消息。不会拖慢回复。 |
| 新对话的第一条消息 | 附上之前对话中最重要的主题（编号、名称、一句话要点），最多 40 条。 |
| 每条人类消息 | 按词语重合匹配图谱（不调用模型），把最多 5 个相关主题附在消息末尾。 |
| 对话旧内容每次请求超过约 24k token | 在下一轮开始时，把旧轮次替换为一份目录：主题列表加每轮一句话。最近 2 轮保持原样。原文不删除，聊天窗口照常显示。 |
| 模型调用 `recall` | `n12`：返回该主题的原文和相邻主题。`t7`：原样返回被折叠的第 7 轮，包括工具输出。 |

## 命令

在对话中输入（菜单弹出时先选 `context-graph`，再输入后面的词）：

- `/context-graph`：状态，包括主题数、待索引轮数、是否有新版本。
- `/context-graph build`：立即索引当前对话。
- `/context-graph fold`：立即索引并折叠旧轮次。
- `/context-graph find 关键词`：查找相关主题。

## 安装与更新

插件 → 添加插件 → 官方 npm 源 → 输入 `dsh-context-graph`，安装后完全重启应用。

有新版本时，你的下一次回复末尾会提示一次，`/context-graph` 的第一行也会显示。更新方法：打开本插件 → 卸载 → 添加插件 `dsh-context-graph@新版本号` → 重启。务必写明版本号：dsh 的 pnpm 默认会暂缓刚发布的版本。

## 关于费用

DeepSeek 对重复发送的已缓存输入只收约 1/30 的价格，而每次折叠都会让缓存重新开始一次。所以折叠只在旧内容很大时、并且目录不到原内容一半时才发生。短对话里它什么都不做。最大的收益来自新对话：不用重复解释，图谱已经记得之前的决定。

## 设置

默认值见 [cordis.patch.yml](cordis.patch.yml)。如果你的对话模型是"思考型"模型（例如 Qwen3）而且较慢，可以用 `provider` 和 `model` 让索引改用更快的模型。
