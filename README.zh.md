# 上下文图谱（dsh-context-graph）

DeepSeek Harness 插件：给每个对话一张小型记忆图谱，由你决定何时开启。同一工作区里的其他对话会收到几行指向过往结论的提示，模型需要细节时再取回原文。旧消息不再重复发送，结论也不会丢失。

第一原则：在不损失质量的前提下减少输入 token。没有在某个对话里运行 `/context-graph on`，插件不会往请求里加任何内容。

## 它做什么

在对话里运行 `/context-graph on` 之后：

| 时机 | 发生了什么 |
|---|---|
| `/context-graph on` | 立即索引当前对话，之后每 4 轮人类发言再索引一次：一次小型模型调用把主题写进 `.context-graph/chats/<对话>/graph.json`，并原样保存被引用的消息。不会拖慢回复。 |
| 开启后的第一条消息 | 附上本工作区已共享的对话列表（最新在前）：对话编号、日期、标题、主题数。 |
| 每条人类消息 | 按词语重合匹配其他已共享对话的主题（不调用模型），把最多 5 个相关主题附在消息末尾。唯一且很短的命中会直接附原文。 |
| 消息里提到时间 | “昨天”“上周”“11月1日”“2026-11-01”……先搜那个时间段：先按对话，再按主题，最后才搜全部。没有命中时，列出那段时间的对话。 |
| 模型调用 `recall` | `c3n12`：该主题的原文和相邻主题。`c3`：某个对话的主题列表。`2026-11-01`：那天的全部对话和主题。`t7`：当前对话第 7 轮的原文。 |
| `/context-graph share` | 让工作区里的其他对话看到本对话的图谱。只是一个标记，不复制、不合并。 |

设计规则：

1. **不开不动。** 没有运行 `on` 的对话不会被索引，也不会收到任何附加内容。
2. **没有原文不写入。** 主题只和它来源的原始消息一起保存。要点是指针，不是记录。
3. **只组织，不合并。** 每个对话的图谱留在自己的文件夹里，带自己的日期。编号带对话号（`c3n12`），每个主题都能追溯到来源对话。
4. **时间是第一过滤条件。**
5. **只在末尾追加**，保住服务商的前缀缓存。隐藏或折叠旧轮次不是本插件的工作。

## 命令

输入 `/context-graph`，在菜单里选中后再输入后面的词：

| 命令 | 作用 |
|---|---|
| `on` / `off` | 开启或关闭本对话的记忆。`off` 保留图谱文件。 |
| `share` / `unshare` | 允许或停止工作区里的其他对话使用本对话的图谱。 |
| `stats`（默认） | 记忆状态、主题数、共享对话数、待索引轮数、token 计数。 |
| `build` | 立即索引当前对话。 |
| `map` | 工作区里的全部对话（最新在前）及其主要主题。 |
| `find 关键词` | 在已共享对话里查找；时间词会缩小范围。 |

结果显示在 dsh 自带的命令卡片里：第一行是摘要，展开看详情。

## 安装与更新

插件 → 添加插件 → 官方 npm 源 → 输入 `dsh-context-graph`，安装后完全重启应用。

有新版本时，你的下一次回复末尾会提示一次，`/context-graph` 的第一行也会显示。更新方法：打开本插件 → 卸载 → 添加插件 `dsh-context-graph@新版本号` → 重启。务必写明版本号：dsh 的 pnpm 默认会暂缓刚发布的版本。

## 文件

```
.context-graph/chats/<对话>/meta.json    编号、标题、开始/最近时间、轮数、memory、shared
.context-graph/chats/<对话>/graph.json   主题与链接，每个主题带时间
.context-graph/chats/<对话>/src/<id>.md  每个主题背后的原始消息
```

## 已知限制

- 重启后，续聊的第一次索引会重读整个对话（编号复用，不会重复）。
- 两个代理同时写同一个对话的图谱：后写的覆盖先写的。
- 子代理会话不索引，也不附加记忆。
- 对话标题暂用第一条消息的缩写。
- 侧边栏的可视化图谱页面尚未实现，`/context-graph map` 是文字版。
